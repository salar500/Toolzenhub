Candidates: U1 directory items, U2 search system, U3 date affordances, U4 Date Difference presets, U5 Gratuity default, U6 Featured Tools, U7 article imagery, U8 Practice Labs hub (only if the owner approves option P1, doc 05), N1 Risk-Reward calculator. Spike criteria for N7 and the B candidates are at the end. IDs are traceable: FR (requirement), AC (acceptance), TO (test oracle). Common rules for all: preserve every URL, canonical, catalog id and calculation; no nested interactive elements; 44 px targets; visible keyboard focus; text never carries meaning by colour alone; no external request; `textContent` for user text; verification follows rulebook section 10 (risk-based, one worker, manual-first, high-risk tested now). **None of these is approved to build by this document.**

## U1. Discoverable, consistent directory items

- **Problem and audience:** visitors scanning All Tools cannot tell what is clickable, and calculators look different from other tools (doc 02 D2). Everyone, mostly first-time visitors.
- **Journey:** All Tools, scan a section, pick a tool by name and one-line description, open it. Or search, same item pattern in results.
- **FR-U1-1** One item pattern for every published tool in every section: icon, title, one-line description from the catalog, whole item activates the tool. **FR-U1-2** The pattern uses one primary link whose area covers the item (a stretched link), with no second link or button inside it (nested interactive elements are forbidden). **FR-U1-3** Section and category heading links stay separate from item links. **FR-U1-4** Calculators gain their catalog description; no text is typed into the directory. **FR-U1-5** Hover, focus-visible, active, and a pressed state; focus outline at least 3:1. **FR-U1-6** Search results on this page use the same pattern; the no-match state keeps its section links. **FR-U1-7** No coming-soon item is styled as a tool (rule 4.4); the "Coming soon" lines follow O-5.
- **States:** default, hover, focus, active, long title wrap at 320 px, no description. **Keyboard:** one tab stop per item; Enter opens. **A11y:** the accessible name is the title; the description is exposed through `aria-describedby`.
- **TO:** an automated check that every published tool has exactly one link in the directory and that no item contains another interactive element; counts equal the catalog (54). **Provenance:** catalog only. **Privacy, SEO, perf:** none, none (links already in HTML), no added requests.
- **AC-U1-1** 54 items, each one link, all routes unchanged. **AC-U1-2** No nested interactive element. **AC-U1-3** Same markup class for calculators and others. **AC-U1-4** Keyboard and 320 px review done. **Out of scope:** new categories, header changes, ranking.

## U4. Date Difference presets

- **Semantics (must be shown on the page):** *difference* = end date minus start date in calendar days. *Inclusive count* = difference + 1 (both end days counted). Calendar addition: start + N calendar days. Business-day addition is a different tool (Business Days Calculator) and is not used here.
- **FR-U4-1** A "Quick fill" row under the two fields: **Today to today**, **Today + 6 days**, **Today + 7 days**, **Today + 30 days**, **Month start to today** (final set is the engineer's call within these). Each button writes both existing fields and triggers the existing calculation; it does not add a new engine. **FR-U4-2** Button labels name the result: for example "Today to +6 days: 6 days apart, 7 counted including both days". **FR-U4-3** An optional "Count both end days" display line, off by default, shows the inclusive count beside the standard difference; it never replaces it.
- **TO (independent, hand computed):** start 2026-10-31: +6 gives 2026-11-06 (difference 6, inclusive 7); +7 gives 2026-11-07 (7, 8); +30 gives 2026-11-30 (30, 31). Month rollover 2026-01-31 +30 gives 2026-03-02. Leap year 2028-02-28 +1 gives 2028-02-29; 2027-02-28 +1 gives 2027-03-01. Year rollover 2026-12-31 +1 gives 2027-01-01. Arithmetic uses calendar fields, not milliseconds, so a daylight-saving change cannot move a date.
- **AC-U4-1** All oracle rows pass. **AC-U4-2** Presets change only the two fields. **AC-U4-3** Existing results for typed dates unchanged. **Out of scope:** new calculation modes, time zones.

## N1. Stock Risk-Reward and Position Size Calculator

- **Problem and audience:** a trader or student wants the exact distances, the ratio and a position size before entering a trade, with costs. Home: Calculators, category Investment (or "More"; rule 4.1: decide in the spec). Not investment advice.
- **Inputs:** side (Long or Short), entry, stop, target, optional account size and risk percent (or a risk amount), optional fee percent per side and flat fee per order, optional slippage per unit. Prices are positive numbers in the same unit; quantity is a whole number.
- **Formulas (unrounded, round only for display):** Long: risk per unit = entry - stop; reward per unit = target - entry. Short: risk = stop - entry; reward = entry - target. Ratio = reward / risk. Risk amount = account x risk percent. Quantity = floor(risk amount / risk per unit). Cost-aware: entry' = entry + slippage and stop' = stop - slippage and target' = target - slippage (long; mirrored for short); fees = fee% x (entry' x qty) + fee% x (exit' x qty) + 2 x flat, where exit' is stop' in the risk case and target' in the reward case; net risk = qty x (entry' - stop') + fees; net reward = qty x (target' - entry') - fees; effective ratio = net reward / net risk; quantity with costs = floor((risk amount - 2 x flat) / ((entry' - stop') + fee% x (entry' + stop'))).
- **Validation (specific, located):** long needs stop < entry < target; short needs target < entry < stop; equal or zero distances are invalid; zero, negative and non-numeric prices rejected; risk percent in (0, 100]; quantity zero is shown as "the risk amount is smaller than the risk on one unit". A stop beyond the entry in the wrong direction explains how to fix it. Maximums stated on the page.
- **UI:** automatic result (rule 7.9); result block first with ratio, risk amount, reward amount, quantity and position value, assumptions beside the numbers; a compact visual of stop, entry, target on one scale (inline SVG with labels). Copy and reset. Mobile at 320 px, 44 px targets, `inputmode="decimal"`.
- **Honesty (rules 3.3, 3.5, 3.7):** states it is arithmetic, not a signal, does not call a ratio good or bad, says gaps and market conditions can fill a stop away from the stop price, uses "estimate" and "scenario", never "safe" or "guaranteed", shows the commonly cited ratios only as reference points if included at all, and states that fees and slippage are the user's inputs.
- **TO (independent):** hand-computed vectors: long 100 / 95 / 115: risk 5, reward 15, ratio 3, account 100,000 at 1% gives risk amount 1,000, quantity 200, position value 20,000. Short 100 / 105 / 85 gives the same numbers. With 0.1% fee per side and slippage 0.05: effective values computed by hand and by a second implementation in the test, which must agree to the display precision. Property tests: swapping side and mirroring prices gives equal outputs; ratio is monotonic in target.
- **Data provenance:** formulas from the cited public sources (doc 00), arithmetic only; no market data. **Privacy:** local only. **SEO:** one primary page, true aliases ("risk reward ratio", "position size calculator"), no article required; an article only if it answers a question the page does not. **Performance:** pure module, no dependency.
- **AC-N1-1** All oracle vectors pass. **AC-N1-2** Invalid price orders rejected for both sides. **AC-N1-3** No live price, no external request. **AC-N1-4** 320 px, keyboard and screen-reader semantics reviewed (screen reader NOT RUN unless done). **AC-N1-5** Catalog, search, sitemap and canonical correct. **Out of scope:** brokerage or price feeds, tax, leverage, margin calls, options, journaling or saved trades (rule 7.7).
- **Dependencies:** a Tool Pack spec first (rule 9.5), which must also answer rule 14 and the AI-era question (exactness, no prompt, the cost-aware sizing).

## Spike and validation criteria for the B candidates

- **AC-SQL-SPIKE (N7):** loader plus wasm measured and reported (gzip); a worker terminates a runaway query within 3 s; peak memory for 50,000 rows reported on the 4 GB laptop; first query within an acceptable time on a throttled mobile profile; MIT licence text confirmed; no network request after load; a result set comparison produces a deterministic pass or fail. Fail any, and SQL is dropped or reduced.
- **AC-PDFIMG-SPIKE (N4):** PDF.js licence and size confirmed; a 50-page file renders page by page within a stated memory ceiling with pages released; failure is graceful for encrypted or corrupt files.
- **AC-N2 (page numbers and watermark):** output reopens in the vendored library, page count equal, original unchanged, text embedded with a font that covers the entered characters or the entry is refused with a message.
- **U9 sliders:** the field inventory exists; every slider has a linked number, `min`, `max`, `step`, label and unit; typing a value outside the slider range is accepted if valid and the thumb clamps visually; no recalculation loop; keyboard arrows, Home, End, Page keys work.
